# 视界巡警评审运行指南

从仓库根目录操作。核心链路可以先用本地图片和录像验证。完整业务工作台另需 MySQL、Redis 和摄像机 SDK。

## 环境与依赖

| 模块 | 环境与依赖 | 监听端口 |
| --- | --- | --- |
| Web 前端 | Node.js 20 或 22 LTS，按公开的 npm 锁文件安装 | 8080 |
| Java 业务服务 | JDK 17、Maven 3.9、MySQL 8、Redis，依赖见 pom.xml | 8081 |
| 人车识别 | Python 3.11 或 3.12，依赖见 scan/Detection/requirements-runtime.txt | 5002 |
| 监控检测与告警 | 共用 Python 运行依赖，MySQL 保存业务记录 | 5000 |
| 本地录像格式转换 | imageio-ffmpeg、ncnn，按需开启 | 5003 |

建议使用 Chrome 或 Edge。相机 SDK 以其提供的操作系统、JDK 和原生库组合为准。下列步骤用于本地评审。

## 1. 独立验证人车识别

1. 在同一 Python 环境安装运行依赖。

~~~powershell
Set-Location .\scan\Detection
python -m pip install -r requirements-runtime.txt
~~~

2. 将项目组单独提供的评审用权重放入 **scan/Detection/models/yolov8l.pt**。Git 仓库提供的是代码及启动说明。用 PowerShell 的 Get-FileHash 核对该文件，SHA-256 应为 **18218ea4798da042d9862e6029ca9531adbd40ace19b6c9a75e2e28f1adf30cc**。同名的其他权重可能不匹配。
3. 用自备或获授权的 JPG/PNG 图片与 MP4/AVI 录像进行功能验证。在 scan/Detection 下执行：

~~~powershell
python -m unittest -q test_original_recognition
python .\verify_original_recognition.py --image "D:\review\frame.jpg" --video "D:\review\clip.mp4" --output "D:\review\verification-result"
~~~

输出目录在执行前应不存在。脚本依次检查模型校验、实际图片和录像识别、最后结果帧及资源释放。需要网页入口时，从该目录运行 python original_recognition.py，配置入口为 http://127.0.0.1:5002/original/config。本地图片和录像推理独立于业务数据库。运行模型会产生检测结果，单段验证结果用于核对功能链路。

## 2. 配置完整工作台

从根目录复制本地模板：

~~~powershell
Copy-Item -LiteralPath .env.example -Destination .env
Copy-Item -LiteralPath .\station-monitoring-banckend\src\main\resources\application.example.yaml -Destination .\station-monitoring-banckend\src\main\resources\application.yaml
~~~

填写 .env 文件中的 MySQL 连接和 Redis 配置。DETECTION_DB_* 是 Java 与检测服务共用的数据库变量。Redis、邮箱和数据库各有独立密码字段。邮箱验证码、DeepSeek 助手和额外转码服务按需配置。保留 .env.example 作为可提交模板。

每个需要启动 Java 或 Python 服务的 PowerShell 窗口，都先在仓库根目录执行以下命令，把本地 .env 加载到当前进程。值按等号右侧原样读取，含特殊字符的密码直接写在值的位置，无需额外添加引号。

~~~powershell
Get-Content -LiteralPath .env -Encoding utf8 | ForEach-Object {
    if ($_ -match '^([A-Z_][A-Z0-9_]*)=(.*)$') {
        [Environment]::SetEnvironmentVariable($Matches[1], $Matches[2], 'Process')
    }
}
~~~

启动 MySQL 与 Redis。由数据库管理员在**全新本地演示实例**导入 station-monitoring-db/station_monitoring_schema.sql，默认建立 station_monitoring 库。该脚本包含建表语句及 DROP TABLE，现有业务库请按部署差异核对迁移。为 .env 指定的应用用户授予该演示库所需权限，监控检测服务初始化时需要创建和维护其事件表。首次进入使用网页的账号注册入口创建普通评审账号，管理员功能使用团队单独提供的评审账号。

Java 构建需要摄像机厂商 SDK。将合法取得的 netsdk-1.0-demo.jar 放到 **station-monitoring-banckend/src/main/resources/libs/**，配套原生库按厂商说明配置。评审方如需运行完整后端，可联系项目组通过评审指定渠道取得兼容版本。到位后执行：

~~~powershell
Set-Location .\station-monitoring-banckend
mvn spring-boot:run
~~~

在各自终端启动其余服务：

~~~powershell
# 终端 2，仓库根目录
Set-Location .\scan\Detection
python -m pip install -r requirements-runtime.txt
python detection_service.py

# 终端 3，仓库根目录
Set-Location .\scan\Detection
python original_recognition.py

# 终端 4，仓库根目录
Set-Location .\station-monitoring-frontend
npm ci
npm run serve
~~~

如需录像格式转换，可在 scan/Detection 安装 imageio-ffmpeg 与 ncnn 后运行 python coupler_service.py。Java 侧导入录像需要转码时，将有授权的 FFmpeg 可执行文件路径设置到 RAIL_FFMPEG_PATH，或加入 PATH。

最后检查以下地址，再登录工作台导入站场录像：

| 地址 | 核对 |
| --- | --- |
| http://127.0.0.1:8080/ | 工作台可以打开 |
| http://127.0.0.1:8081/health | Java 服务健康检查 |
| http://127.0.0.1:5000/health | 摄像头检测服务就绪 |
| http://127.0.0.1:5002/original/config | 人车识别服务声明模型为 yolov8l.pt |

固定摄像机画面、告警写入和作业处置需要现场或隔离演示的实际设备与业务数据。没有机位时可用本地录像展示识别与回看。

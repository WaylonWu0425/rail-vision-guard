# 视界巡警作业感知升级设计与实施报告

更新日期：2026-11-14。适用对象：比赛演示原型；现场应用须另行完成场景评估、数据授权、设备安装和企业验收。

## 一、定位和使用者

产品定位为站场视频辅助核查与证据追溯工作台。值班人员需要迅速找到值得复看的片段；作业管理人员需要复盘一次作业；安全管理人员需要核查结论和处理记录。模型输出是待核查线索，不能直接判定违规、连挂妥当或发出行车指令。

## 二、现有基线与关键问题

主系统已有摄像头接入、人员/车辆 YOLO 检测、跟踪、区域规则、告警、录像、任务和三维总览。独立的“作业感知”页面已接入老师提供的 NCNN `best12_20.param/.bin`，对图片或视频当前帧输出货车及车钩相关类别、置信度和预测框。当前识别结果只保持在页面内，视频时间轴没有检测事件标记，也没有逐条人工复核记录。浏览器尚未获取安卓端的声音、加速度或 GPS 记录；距离没有相机标定，不显示测量值。

老师的 Android 应用还有近远目标选择、基于相机参数的距离求解、声音阈值与加速度时窗判断。这些能力来自特定安装与采集条件；不能把 APK 内置参数用于任意站场摄像头，也不能把两路镜头称作经过验证的双目测距。手机手持、放在桌上、固定在站旁或安装在车辆上的声音与运动含义不同。接入前必须确定安装位置和同步方式。

最需要回答的业务问题：识别框是否对应真实车钩；测得的是相机到目标还是两车钩间距；遮挡和夜间如何失效；声音/冲击与画面是否来自同一次作业；谁负责核查、确认和归档。

## 三、设计原则

1. 以“一次作业”组织原视频、模型结果、有效性、人工结论和回放入口。每个结果带来源、视频时间点、模型配置和处理状态。
2. 视觉、距离、声音、冲击分别显示可用性和时间戳。信息缺失显示原因；过期数据不继续显示为当前值。
3. 距离估计只在确认相机、分辨率、焦距、安装姿态、目标几何与实测对照后启用。`3 m` 模型切换阈值与铁路作业中的距离信号不是同一概念。
4. “疑似接触”可以作为复核提示；“连挂妥当”须遵循实际作业确认流程，不能由单帧、声响或振动单独给出。
5. 事件需要能从检测跳转录像，人工可确认、排除或标注证据不足；自动推荐处理人若引入，也由有权限人员确认。

## 四、实施顺序和交付

| 阶段 | 具体改动 | 交付及验收 | 前提 |
| --- | --- | --- | --- |
| 1. 可复盘视频识别 | 增加老师 APK 输入尺寸/阈值对照配置；每次识别记录视频时刻、原画面、检测结果和人工复核状态；点击记录返回相应位置 | 同一视频中可逐帧识别、在时间轴查看结果、跳转复看并修改复核结论；切换文件不串记录 | 现有 NCNN 权重及本机服务 |

阶段 1 的 `apk320` 仅对齐已核查的长边输入尺寸与页面可选阈值，现有网页解码、填充、NMS 与 Android 原生实现的逐项一致性仍须用相同原帧作输出对照，不能将该选项称为已复刻 APK。网页默认 `web640` 保留。记录目前只存在浏览器本次会话内，最多保留最近 30 次识别；正式归档和服务端任务联动属于阶段 4。

## 五、页面信息结构

首页继续承担设备状态和待核查事件总览。作业感知页以真实画面为主，右侧展示模型配置、车钩目标和各路数据有效性，底部显示可点击的检测时间轴与人工复核记录。无同步双路输入时只显示单路视频。核查页显示原始证据、人工结论和任务入口；三维站场仅定位已绑定实际设备，其他位置明示为示意。

## 六、竞赛和采购演示

演示顺序：选择经授权的真实视频 → 定位一次真实检测 → 查看原帧、框和模型配置 → 跳回视频复核 → 记录人工判断 → 展示一例遮挡或无标定时的失效提示。主系统的人员/车辆检测与车钩模型分开说明。示例素材、实时结果和人工判断分别标记。不能把 `videotest.mp4` 的人员画面说成车钩连挂实测。

企业试点需要针对具体岗位和机位约定验收口径：检测漏检/误检、同条件测距误差和无效输出比例、多源时间同步误差、人工查找证据时间、断网恢复、录像保存与检索、数据授权与运维责任。数字须来自同一测试条件下的实测，不能从模型名称或 APK 演示推算。

## 八、阶段 1 当前实施记录

截至 2026-11-12，作业感知页已增加实际推理时间轴节点、最多 30 条本次会话检测记录、点击跳回视频时刻、逐条人工判断和本地 JSON 导出。原视频及原始告警库未修改。NCNN 服务新增 `web640` 与 `apk320` 可选输入配置，前端只在服务健康检查明确报告支持时开放 320 选项；运行中的旧服务继续走原 `/predict` 接口。`apk320` 能执行推理，但尚未用同一批真实车钩帧与安卓输出核对类别、框和分数。

2026-11-13 继续实施：页面增加 1/2/5 秒间隔的顺序抽帧扫描、进度和停止操作。长视频最多在全片均匀抽取 60 帧，记录上限同步调整为最近 60 条；未抽取的时刻不能推断没有目标。此功能在浏览器中驱动视频解码和逐帧服务请求，没有让检测结果自动变成报警。两种推理配置的本机 HTTP `/predict` 均返回实际处理画面，前端生产构建通过；近距离车钩画面的效果仍待新素材验证。

同日补充验证：文件选择已接受 AVI，现有 `列车运行.avi` 通过本机 `/transcode` 实际转换为浏览器可用的 MP4（HTTP 200，约 77.5 MB，单次耗时约 9.7 秒）；这只验证转码链路，不等于已完成浏览器端整片扫描。修复了视频首帧尚未解码时扫描从 0 秒开始可能超时的问题。修改后前端生产构建通过。当前实测远景素材不适合作为车钩识别成功案例；待取得近景视频后，应在浏览器依次检查播放、抽帧、记录跳回与人工复核，并与老师 APK 同帧对照。

当前现场数据仍有缺口：没有可对应当前站场相机的标定及已量测距离样本，没有与视频同步的真实音频/加速度导出，也没有经站场岗位确认的处置规则。第二阶段软件入口与现场验收状态见第十节。

## 九、现场素材初筛：列车运行.avi

用户提供的 `真实车站监控视频/列车运行.avi` 为 1280×720、20 帧/秒、约 106.3 秒的远距离站场俯视录像。抽查 0、10%、25%、50%、75%、90% 和末帧，均能看到敞车运行，但车钩与车辆接触部位在这些画面中无法辨清。相同七帧分别使用 `web640` 与 `apk320` 推理，14 次调用均返回空目标。此结果只描述抽样帧，不代表逐帧评测或模型整体精度。

素材可用于展示视频导入、时间轴、列车运行场景及模型在不适合机位下的诚实空状态；不宜作为车钩识别、接近测距或连挂接触的成功演示。后续应补充经授权的车厢端部/车钩可见、接近过程连续且机位信息明确的原始录像。若视频中途变焦或转动，固定机位标定不能直接沿用。

## 十、阶段 2 相机至车钩参考面测距

### 1. APK 核对结果

APK 内的 `assets/best12_20.param/.bin` 与老师另给的模型文件 SHA-256 相同。APK 的 ARM64 原生库 `libyolov8ncnn.so` 中，`Yolo::detect` 调用 OpenCV `solvePnP`（ARM64 调用指令地址 `0x357d04`）。库内还有两路相机的距离日志、`outDistance` 及距离滤波符号。反编译的 `MainActivity.updateDistance` 把接收到的整数显示为厘米，非零读数没有后续更新时约 3 秒清除。APK 包内没有独立的相机标定文件，现有资料也没有给出可绑定到实际摄像头的视频流标定结果。

老师的《测距原理说明》给出了近段 PnP 和从斜距换算两钩间距的设计。文中约 0.5 × 0.4 m 的目标面和偏移补偿是该方案的名义值。网页只实现相机光心至矩形参考面中心的斜距，使用各机位实测尺寸和对应图像角点，手机与站场机位分别建档。手机厘米读数可以作为并列对照记录，独立实测值需要用同一参考点、用量具测得。

### 2. 标定、计算与门槛

- 网页进入「作业感知 → 测距验证」，下载 JSON 模板。每份档案绑定一个相机和镜头配置、一组内参与畸变、一种尺寸实测的平面参考目标。换相机、焦距、裁切或安装条件须建立对应档案。模板留空的数值需要填写实际数据，固定分辨率必须匹配。档案可导入和导出，在当前页面会话中使用。
- 确认目标上的四个实物角点与测得的矩形宽高对应。按左上、右上、右下、左下取点，四点需清晰、完整可见。OpenCV 平面 PnP（IPPE）求解位姿，筛选正深度解，选重投影误差最小者。IPPE 无合格解时尝试迭代 PnP，使用同样的准入条件。平移向量的模长为相机光心到参考面中心的直线距离。像素重投影误差用于筛查图像几何，距离精度用独立实测误差评价。参考 [OpenCV PnP 位姿求解说明](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)。
- 每帧录入相机光心到同一参考面中心的量测距离、量具及起止点。试验前在档案中填写像素误差、平均绝对误差与单样本绝对误差上限。软件按不同距离至少三组有效对照、所有样本均有效且满足设定误差门槛判断是否开放本档案估算。覆盖范围仅取本批实测样本的最小值和最大值，两端之间仍需结合实际取样密度理解。三点是本原型的最低对照门槛。
- 通过后可选同条件的新帧再次标点，输出距离、重投影误差及档案的实测范围和误差统计。无档案、未通过对照、分辨率不匹配、角点不完整、几何误差过大或越界时不输出该帧的距离。界面分别展示这些原因。

### 3. 验证状态与待采资料

软件验证使用 OpenCV 生成有已知位姿、带畸变的矩形投影，核对三组距离、比较和估算 HTTP 接口，以及无档案、未通过实测、错分辨率、裁切和越界分支。浏览器使用独立挂载的真实测距面板与运行中的 5003 服务，验证档案导入、空档案门槛、点选四角、确认同机位、估算及撤销后清除读数。正对相机的测试图触发 IPPE 无有效解，补充迭代法后同一用例通过。前端生产构建通过。上述合成数据只验证实现与计算一致性。

现场验收需要老师或现场采集人员提供：① 同一设备、镜头与固定焦距下标定得到的内参和畸变系数、标定分辨率及成像设置，② 实际车钩上可明确对应的矩形参考面、四角和中心以及测得的宽高，③ 同一配置下至少三个不同距离的原始清晰帧或视频时刻，以及用独立量具从同一基准到同一参考点测得的距离。先使用 APK 对应的采集设备验证，固定监控相机有自己的独立标定。当前无可配对的现场样本，暂无现场误差与有效量程结论。

## 十一、阶段 3 至 5 的软件实施

### 阶段 3 · 多源时间对齐

在「作业感知 → 作业时间轴」打开视频后，可导入同一次作业的录音和三轴加速度 CSV，分别填写采集位置、同步依据及共同出现的标记时间。CSV 使用 UTF-8，表头为 `time_s,ax_m_s2,ay_m_s2,az_m_s2`，时间按源记录起点后的秒数填入，须非负、严格递增，三轴单位为 m/s²。加速度有含重力、线性加速度和口径未知三种标注。若 APK 使用其他列名、毫秒或其他单位，先核对实际格式和时间基准再转换。

一个同步点只校正起始时间差，两个同步点可按线性模型同时校正时钟漂移，双点结果仅在两同步点之间使用。用视频时间定位录音试听，并展示对齐到视频时刻前后 0.25 秒内的最近三轴样本及实际偏差。音频和加速度缺失、超出范围或时间差过大时显示缺失。加速度的 0.25 秒是界面取样窗口，现场同步误差需靠未参与对齐的共同标记单独核查。录音和加速度变化交由人工结合画面解释。

### 阶段 4 · 人工核查和本地证据归档

从当前画面或时间轴上的检测记录提取证据。归档保存素材名称、文件大小、修改时间、视频秒数、原画面、同帧检测结果和框图，并保存该时刻的录音定位信息、加速度样本与已完成且属于同帧的测距快照。核查人需选择结论并填写说明。后续复核追加新一版，保留之前的结论、人员和时间。

归档使用本浏览器 IndexedDB，按当前界面账号分组。它是本地留痕，账号分组不能替代服务端鉴权或防篡改审计。同一浏览器和同一地址可刷新查阅，支持导出 JSON。视频回看需要重新选中原视频，匹配依据为文件名、大小、修改时间；组合字段只是定位线索。原视频、外部录音和完整加速度 CSV 需随档案单独保存。业务事件类型、岗位权限、处理规则确认后才能将正式告警和任务流转接入。

### 阶段 5 · 现场试用记录

「现场试用记录」提供服务断线与恢复、夜间与遮挡、误报漏检、测距失效、多源对齐与缺失、长时间运行、岗位核查七项检查。每项初始为未执行，选择结果后需要填写实际观察或所缺条件。记录地点、设备、操作人和源素材后，可以导出 JSON；实际试用的场地、机位和岗位人员由现场提供。

日常界面入口称为「连挂复核」。现场试用时，在启动或构建前端前设置 `VUE_APP_FIELD_TRIAL_ENABLED=true`，可显示「现场试用记录」、推理配置与诊断详情。默认隐藏这些验收工具。

### 软件验证

前端生产构建通过。Edge 浏览器在隔离测试页挂载实际作业感知组件并连接本机 5003，使用现有《列车运行.avi》验证转码播放、拖动和推理接口。使用明确标为测试数据的录音及 CSV 验证双点漂移、无匹配时间、试听、拒绝错误表头、切换素材清空对齐。复核归档在测试账号上下文中验证了原帧、同帧模型结果及对齐快照、增加版本、刷新后找回、回跳视频，以及归档和试用记录导出。该次测试覆盖软件链路，三轴配对和试听素材并非现场同步采集，现场试用各项仍待实际执行。
